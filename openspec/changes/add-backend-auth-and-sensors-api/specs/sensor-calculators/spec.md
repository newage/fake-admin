# Spec Delta

## Purpose

Визначає контракт підключуваних калькуляторів над даними датчиків і три шляхи віддачі даних: сирі показання, розрахунок на запит і готові кешовані значення.

## ADDED Requirements

### Requirement: Реєстр калькуляторів
Система SHALL мати реєстр, у який калькулятор підключається, оголошуючи ім'я та режим `live` або `cached`; клієнт API SHALL NOT вказувати режим.

#### Scenario: Реєстрація калькулятора
- **WHEN** калькулятор зареєстровано з режимом `cached`
- **THEN** його результати віддаються з кешу без зміни контракту API

#### Scenario: Невідомий калькулятор
- **WHEN** клієнт просить калькулятор, якого немає в реєстрі
- **THEN** відповідь 404

### Requirement: Режим live
Для калькулятора з режимом `live` система SHALL обчислювати результат під час запиту.

#### Scenario: Розрахунок на запит
- **WHEN** клієнт просить результат `live`-калькулятора для датчика
- **THEN** результат обчислюється з поточних даних і повертається у відповіді

### Requirement: Режим cached
Для калькулятора з режимом `cached` система SHALL читати результат із таблиці готових значень (запис, ключований калькулятором, датчиком і вікном) і SHALL NOT обчислювати його під час запиту.

#### Scenario: Є готове значення
- **WHEN** для датчика, калькулятора й вікна є запис
- **THEN** відповідь містить значення та час обчислення

#### Scenario: Значення ще немає
- **WHEN** запису немає
- **THEN** відповідь повідомляє, що значення ще не пораховане, без запуску розрахунку

### Requirement: Ендпоінт сирих показань
`GET /api/sensors/{id}/readings` SHALL бути окремим шляхом віддачі сирих показань датчика, доступним ролям за матрицею прав; пагінація й діапазон часу обовʼязкові.

#### Scenario: Датчик не існує
- **WHEN** клієнт викликає ендпоінт для неіснуючого `id`
- **THEN** відповідь 404

#### Scenario: Таблиця показань ще не створена консʼюмерами
- **WHEN** сховище показань недоступне
- **THEN** відповідь 503 з зрозумілою помилкою, а не 500 зі стеком
