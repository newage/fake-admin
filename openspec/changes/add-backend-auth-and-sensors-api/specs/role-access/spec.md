# Spec Delta

## Purpose

Визначає, як система вирішує, чи може роль викликати конкретний API, за матрицею прав, що зберігається в БД.

## ADDED Requirements

### Requirement: Автентифікація захищених маршрутів
Система SHALL вимагати дійсний access-токен на кожному маршруті `/api/*`.

#### Scenario: Без токена
- **WHEN** клієнт викликає `/api/*` без заголовка `Authorization`
- **THEN** відповідь 401

### Requirement: Права ролі за матрицею в БД
Система SHALL дозволяти виклик, лише якщо для ролі користувача в таблиці прав є запис для цього ендпоінта; інакше SHALL відповідати 403. Права SHALL NOT бути зашиті в обробники.

#### Scenario: Дозволена роль
- **WHEN** користувач з роллю `manager` викликає `GET /api/sensors`, і для `manager` є право на цей ендпоінт
- **THEN** запит виконується

#### Scenario: Недозволена роль
- **WHEN** користувач з роллю `user` викликає `GET /api/sensors`, і права немає
- **THEN** відповідь 403 без даних

#### Scenario: Зміна матриці без релізу
- **WHEN** запис про право ролі змінено в БД
- **THEN** наступний запит поважає нове право без зміни коду

### Requirement: Початкова матриця прав
Система SHALL після міграцій мати ролі `admin`, `manager`, `user` і права: `admin` і `manager` на `GET /api/sensors`, `GET /api/sensors/{id}/readings`; `user` без прав на ці ендпоінти.

#### Scenario: Свіжа установка
- **WHEN** міграції виконано на порожній БД
- **THEN** три ролі існують, а матриця відповідає описаній вище

### Requirement: Зарезервоване поле обмежень
Запис права SHALL мати необовʼязкове поле обмежень параметрів; порожнє значення означає «без обмежень», а непорожнє в цій ітерації не інтерпретується.

#### Scenario: Порожні обмеження
- **WHEN** право має порожнє поле обмежень
- **THEN** ендпоінт доступний з будь-якими допустимими параметрами
