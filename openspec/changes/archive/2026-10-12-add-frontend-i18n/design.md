# Design

## Context

Усі рядки UI захардкоджені українською в `app-layout.tsx`, `login-page.tsx`, `sensors-page.tsx`; дати форматуються `Intl.DateTimeFormat('uk-UA')`. SPA роздає nginx статикою, бекенд мови не знає. Шапки на сторінці логіну немає: `AppLayout` обгортає лише захищені маршрути. Жорстка CSP (`default-src 'self'`) допускає переклади лише з того ж origin або з бандла. Мотивація: див. `proposal.md`, повний журнал рішень: `.agents/docs/multilang-decisions.md`.

## Goals / Non-Goals

**Goals:**
- Один реєстр мов, з якого беруться список у перемикачі, Intl-локаль і ресурси.
- Додавання мови без зміни логіки: файл перекладу плюс запис у реєстрі.

**Non-Goals:**
- Англійська, серверна локалізація, nginx/cookie-детекція.
- Ліниве завантаження перекладів, переклад даних із БД (назви й типи датчиків).

## Decisions

**1. Клієнтське визначення мови.** Порядок: localStorage → `navigator.languages` → `uk`. Збіг за основною частиною (`pl-PL` → `pl`). Альтернатива, відкинута: nginx ставить cookie за `Accept-Language`, бо дублює логіку й ламає dev через Vite.

**2. localStorage замість cookie.** Читає тільки фронтенд; cookie їхала б у кожному запиті. Читання й запис у `try/catch`: недоступне сховище не ламає застосунок.

**3. `i18next` + `react-i18next`.** Готові множини (у польській три форми), підстановки, типізація ключів. Альтернатива: власний шар на `Intl.PluralRules` — свій код без екосистеми.

**4. Код мови + реєстр.** Зберігається `uk`/`pl`; реєстр мапить на `uk-UA`/`pl-PL` для `Intl` та задає назву мови для перемикача (власною мовою: «Українська», «Polski»). Альтернатива: зберігати повну локаль — крихкий збіг із заголовком.

**5. Ресурси в бандлі, одна ініціалізація.** JSON-файли на мову в `frontend/src/lib/i18n/locales/`, ініціалізація синхронна до першого рендера (`main.tsx`), тому мигання мовою немає. `<html lang>` оновлюється на `languageChanged`.

**6. Перемикач як окремий компонент.** Рендериться в `AppLayout` справа зверху і на сторінці логіну (там немає шапки, тож у куті сторінки). Використовує нативний `<select>` для доступності без нових UI-залежностей.

**7. Повідомлення — ключі, переклад на рендері.** Zod-схема логіна повертає ключі (`validation.email_required`), `t()` застосовується при показі; схема не залежить від мови на момент створення, тому перемикання працює без перебудови форми. Те саме для мапінгу помилок логіна.

**8. Форматери залежать від мови.** Модульний `Intl.DateTimeFormat('uk-UA')` у `sensors-page.tsx` замінюється хуком, що створює форматер для локалі поточної мови (мемоїзація за мовою).

## Risks / Trade-offs

- [Тести перевіряють українські рядки] → тестовий setup ініціалізує i18n з `uk` і фіксує мову.
- [Пропущені рядки лишаться українською] → тест на однаковий набір ключів у всіх мовах і ESLint/grep-перевірка кирилиці в `src` поза локалями.
- [Польські переклади без носія мови] → позначити переклад до рев'ю; змінюється лише JSON.
- [Фіксований fallback `uk`] → якщо в ключі немає перекладу, показується українська, а не ключ.
